1. Summary and design choices

One application, five views (Geometry, Thermal, Performance, Hardware, Backprop). Launch.exe (tiny Win32 GUI program) starts bin\wb_server.exe hidden on 127.0.0.1, waits for /api/health and opens an Edge app window; the backend exits itself a few seconds after the window closes. No installer, admin rights, terminal or internet.

  • Separation: wb_core (C++17 library: FEA, STL/CSV parsers, thread pool, batch, device mocks, backprop) has no HTTP/UI code and is unit-tested directly; wb_server (cpp-httplib, MIT) only validates and serialises; the UI (plain ES modules + canvas, no CDN) only draws.
  • Why a local web UI: works on a clean Windows 11 PC with no runtime to install; Edge is preinstalled; the same core is reused by wb_cli.
  • Safety: loopback only, Host-header check, X-WB-Client header on every POST, file whitelist, strict parsers (line-numbered errors, NaN/Inf rejected), limits 256 MiB / 3M triangles / 5M rows, 300 MB body cap (HTTP 413).
  • Jobs: one benchmark at a time with progress and Cancel (atomic flag, no partial results).

3. Thermal FEA and verification (Task C)

-kA T'' = qA on [0,L]; L=1 m, A=1e-4 m², k=10 W/mK, q=1e4 W/m³, T(0)=100 C, T(L)=20 C. Two-node elements, tridiagonal assembly, Dirichlet values moved to the RHS, Thomas solve. Exact: T = T0 + (TL-T0)x/L + qx(L-x)/(2k). Midpoint error uses the FE interpolant (Ti+Ti+1)/2 versus exact.

Midpoint error = q h²/(8k) = 125 h² exactly: slope 2. Debugging insight: nodal values are exact to round-off (1e-13), so a nodal-error check cannot reveal discretisation error or a wrong interpolation; verification therefore uses midpoint error, the convergence slope and an independent dense Gaussian-elimination solver. Three injected solver bugs (source term, two Dirichlet terms) were all caught by the tests (tools/mutation_check.sh).

5. Embedded design (Task E) - SIMULATED

All device behaviour is simulated (C++ mocks: discovery, capabilities, connect/disconnect, one telemetry message, injected recoverable TIMEOUT, recovery by reconnect; screenshots 08/09). Example boards are assumptions.

A JTAG adapter is a debug interface, not a compute board: it runs no application, adapts to the target's VTref, and its connector, protocol (SWD/JTAG) and pin ownership differ per target. The software discovers by type and capability and assumes no shared connector, voltage or protocol. Pin numbers are left to each board's datasheet. Safe plan: datasheet review, bench supply with current limit, one device at a time, ground first, read-only (IDCODE, loopback) before any write, level shifter/series resistors where domains differ, timeouts and safe disconnect. Limits: no real drivers, wiring, firmware or FPGA programming.
